1. Where the data came from

The upstream project is Free Money & Contest Ledger, source repo karagemop466-tech/FreeMoneyApps. Its canonical dataset is assets/data.js, which defines window.LEDGER. The upstream file records its own review date as {{upstreamdate}} and its internal pass as S.

At commit {{upstreamcommit}} that file contains {{total}} listings. It is copied verbatim to data/source-ledger.json in this repo, with no edits. Every derived field on this site — prize type, verification level, flags, triage score — is computed from that copy by tools/audit.mjs, so any claim here can be traced back to the upstream text.

Nothing was invented to fill a gap. Where the upstream file has no value, the site shows "Not stated" and raises a flag. There is no inference, no averaging, no "approximately" and no placeholder figure anywhere in the table.

2. The three verification levels

Only three labels appear on a row. They mean precisely this:

BadgeWhat I didCount
Verified here I fetched the operator's own page on {{date}} and read the claim on it. The quoted sentence is printed on the row, with the URL, so you can re-check it in one click. {{verified}}
Official source The row cites a source hosted on the operator's own domain, and it passed every structural check. I did not re-open the page this session, so the figure is the upstream file's claim — plausible and sourced, but not freshly confirmed. {{official}}
Flagged At least one high-severity defect: a non-cash prize, no official source, a mislabelled source, or a row that is not a competition. The reason is printed on the row and repeated on Flagged for review. {{flagged}}

Do not read "Official source" as "confirmed". It means the sourcing rule was satisfied, not that a human opened the page today. Only {{verified}} rows reached the stronger level.

3. Source tiers, and the mislabelling problem

The upstream project defines three tiers and a rule that goes with them:

TierUpstream meaning
officialThe operator's own domain — rules page, game page, or press release.
affiliateA review or SEO site. Allowed as secondary colour, never as the sole basis for a figure.
forumReddit, X. Context only.

The rule: any listing that states a specific prize figure must cite the operator's own rules or game page. Upstream says this rule exists because it was tested — in their 19 Aug audit, 9 of 12 confirmed factual errors traced to an affiliate source.

The audit found the rule is not consistently applied in the data:

  • {{f_noofficial}} rows cite no official source at all. NO_OFFICIAL_SOURCE. Several are still marked live.
  • {{f_tier}} sources are graded official but are not the operator. TIER_MISLABEL. Examples: a press-release wire (prnewswire.com), a broker review aggregator (myfxbook.com, tradingbrokers.com), an affiliate bonus blog (ndfxbonus.com), club and league fan sites (tottenhamhotspur.com, leicestertigers.com), a golf blog (thegolfwire.com) and X posts.
  • {{f_offdomain}} rows have an official source, but not on the operator's domain — so the prize figure still comes from a third party.

The three worst cases. roboforex-demo, fbs-pro-demo and npbfx-demo are marked live and quote precise graded prize tables ($700/$550/$420…, $450/$250/$150…, $1,000/$500/$250…) while their only sources are affiliate bonus blogs. Those are exactly the figures the sourcing rule exists to stop. They appear on the site with blank confirmation and a flag, not as verified numbers.

6. Limits of this audit — read this

Being precise about what this is not is the point of the exercise.

  • Only {{verified}} of {{total}} rows were opened at the operator. The other {{official}} "Official source" rows carry the upstream file's claim plus a working-looking source link. That is a sourcing check, not a fresh confirmation. Treat the prize figures as as-reported until you click through.
  • Status is inherited, not observed. {{live}} rows say live, but I did not poll each operator today. Sports and fantasy contests are seasonal, and several are certainly out of season on {{date}} — MLB Beat the Streak's own rules end the entry period with the 2026 regular season, and its row still reads live. This is recorded on the row and on Flagged for review.
  • Links were not all fetched. Checking several hundred live links from this environment was not possible — outbound access from the build shell is restricted to a host allowlist, and every operator domain is outside it. Link rot is therefore possible on any row. The structural checks confirm every URL is well-formed and points where the row says it does.
  • Eligibility is copied, not re-verified. Age floors, state exclusions and jurisdiction blocks are the most volatile fields in the dataset and the most consequential. The three rows I did verify (CBS, MLB, Metaculus) matched exactly; the rest are as-reported.
  • Prizes change. A "largest stated prize" is the biggest number written in the prize field, not a guaranteed payout. Most of these pay only to the top of a large field, and several only pay if a near-impossible condition is met — MLB's $5,600,000 requires a 57-game hit streak and pays nothing at all if nobody reaches 20.

7. The "best use of time" order

The default sort on All competitions is a triage score out of 100. It is an editorial aid built only from fields already recorded, and it is not a fact about any competition. The weights:

ComponentPoints
Genuine free path to the cash prize+25 (partial +10, fee required 0)
Prize is cash (cash + other +20, unstated +5, non-cash 0)+25
Largest stated dollar figure, on a log scale, cappedup to +20
At least one official source on the operator's own domain, with no mislabelled source+15
Status live (caution +4)+10
No flags at all+5

Because a big headline number earns points, the score rewards exactly the thing worth being suspicious of. Always take the second step: read the cash-out field and the rules link on the row before committing time.

8. Reproducing this

The pipeline is two scripts and needs nothing but Node:

FileRole
data/source-ledger.jsonVerbatim copy of upstream assets/data.js → window.LEDGER.
tools/audit.mjsClassifies every row, raises flags, assigns verification levels and the triage score. Writes data/audit-report.json and assets/data/competitions.json.
tools/build-site.mjsWraps page bodies in one shared shell and injects audit counts into the prose, so no number on the site is hand-typed.
tools/check-links.mjsVerifies that every internal link resolves to a file that exists and that every external URL on the static pages is well-formed and present in the dataset.

Build: node tools/audit.mjs && node tools/build-site.mjs && node tools/check-links.mjs

Upstream dataset reviewed {{upstreamdate}} at commit {{upstreamcommit}}. This audit and every page build ran on {{date}}. If an operator changes its rules after that date, the operator's rules win — as they did before.
